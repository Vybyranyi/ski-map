# Ski Map — Буковель

Мобільний веб-застосунок (Next.js, PWA) на основі офіційної карти трас Буковеля: фільтр трас за складністю,
плани катання на кілька днів із відмітками «пройдено», живий статус і GPS-точка.
Лише для особистого використання (карта й іконки належать Буковелю, не перемальовуємо).

## Рішення

- Без БД. Стан (плани, відмітки, фільтри) — у `localStorage` + експорт/імпорт JSON.
- Деплой на Vercel: звичайний Next.js, один Route Handler проксує живий статус (CORS у Буковеля немає).
- Лише українська мова.
- Фільтр: чотири незалежні перемикачі (зелені / сині / червоні / чорні), лише «сховати».
  Підйомники, що ведуть тільки на сховані траси, теж ховаються.
- План — впорядкований список сегментів (траса/підйомник) з прапорцем «пройдено», одну трасу можна додавати кілька разів. Планів кілька (по днях).
- Планувальник вільний, без графа зв'язків (граф — можлива пізніша фіча).
- GPS: гомографія «координати → піксель карти» за опорними точками (станції підйомників з OSM). Очікувана точність — десятки метрів.

## Дані карти

Карта Буковеля — растровий фон (`public/map/background.webp`, 2865×1648) + SVG-оверлей з лініями.
Фон — оригінальний JPG Буковеля, конвертований у WebP (q82, 1,2 МБ замість 2,3 МБ; `sharp` із залежностей Next).
Усе в SVG намальоване одним помаранчевим кольором, тому колір за складністю задаємо самі (CSS по `data-diff`).

| Файл | Що це |
| --- | --- |
| `data/raw/map-dom.html` | серіалізований DOM `https://bukovel.com/map-new/` (SVG збирається React-ом, тож знімаємо headless Chrome) |
| `data/raw/map-data.json` | `GET /api/v1/ski/map/trails/lifts/` — складність, висоти, довжина, підйомник траси |
| `data/raw/status.json` | `GET /api/v2/status-lifts-trails` — типи, примітки, живий статус |
| `src/data/generated/overlay.svg` | очищений оверлей зі `data-kind` / `data-trail` / `data-diff` / `data-lift` |
| `src/data/generated/resort.json` | нормалізовані траси й підйомники |

Перегенерація: `npm run build:map` (читає `data/raw`, пише в `src/data/generated`).

Оновити сирі дані (кроки вручну):

```bash
curl -o data/raw/map-data.json https://bukovel.com/api/v1/ski/map/trails/lifts/
curl -o data/raw/status.json   https://bukovel.com/api/v2/status-lifts-trails
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --virtual-time-budget=15000 \
  --dump-dom "https://bukovel.com/map-new/?lang=uk&from-site=true" > data/raw/map-dom.html
```

### Пастки в даних Буковеля

- `difficultyLevel` у v2 завжди `BLUE` — ігноруємо. Складність беремо з v1 (`difficulty`); вона збігається з типом у v2 (EASY → blue, MEDIUM → red, HARD → black, PLAYGROUND/TRAINING → green).
- Назва в SVG-id може розходитися з JSON: `Track17ABlue` та `Track-7D-blue` у JSON зелені. Складність завжди беремо з JSON за назвою траси.
- Підйомник 1 в SVG має id `Lift1R`, у JSON — `Lift1`.
- Три безіменні шматки ліній у SVG — продовження трас до станцій; власників задано в `SEGMENT_OWNERS` (`scripts/build-map.mjs`).
- Open-підйомники на сайті мають клас `lift--animated` (рухомі штрихи) — можна повторити для живого статусу.

## Карта в застосунку

- Оверлей вставляється як inline-SVG (`src/components/ski-map.tsx`); фільтр і підсвітка — це перемикання атрибутів `data-hidden` / `data-selected` на групах, без перерендеру React.
- Лінії мають сталу товщину на екрані: CSS-змінна `--zoom` (оновлюється з затримкою після жесту) у `calc(3px / var(--zoom))`.
- Тап по тонкій лінії: у кожну лінію додається прозорий «двійник» `.hit` із товстим штрихом. Мітки й іконки мають пріоритет над хітбоксами (див. `pickGroup`).
- Фільтр ховає також з'єднання (`connector`) і підйомники, усі траси яких приховані. Стан фільтра — `localStorage` (`ski-map:filters`), підтягується в ефекті (`skipHydration`).
- Тап відрізняємо від жесту власним порогом (10 px / 500 мс); відпускання слухаємо на `window`, інакше жест «залипає», якщо відпустити поза картою.

## Плани

- Стор `src/lib/plans-store.ts` (zustand + `localStorage`, ключ `ski-map:plans`): плани → впорядковані елементи `{type: trail|lift, ref, done}`. Одну трасу можна додати кілька разів, кожне входження має свій прапорець.
- Додавання: кнопка «Додати в план» в інфо-панелі вибраної траси/підйомника; якщо планів нема, створюється «День 1».
- Панель плану (`plan-panel.tsx`): тап по рядку — «пройдено», «Змінити» — порядок (▲▼), видалення, перейменування, скидання прогресу, видалення плану; кнопка-приціл показує елемент на карті (і повертає приховану складність).
- На карті елементи активного плану товщі, пройдені — світліші (`data-planned` / `data-done`).
- Резервна копія: експорт у файл / у буфер, імпорт з файлу / з буфера (`plan-io.ts`). Імпорт завжди додає плани як нові (нові id), невідомі траси відкидає й повідомляє.
