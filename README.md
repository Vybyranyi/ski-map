# Ski Map — Буковель

Мобільний веб-застосунок (Next.js, PWA) на основі офіційної карти трас Буковеля: фільтр трас за складністю,
плани катання на кілька днів із відмітками «пройдено», живий статус і GPS-точка.
Лише для особистого використання (карта й іконки належать Буковелю, не перемальовуємо).

## Рішення

- Без БД. Стан (плани, відмітки, фільтри) — у `localStorage` + експорт/імпорт JSON.
- Деплой на Vercel: звичайний Next.js, один Route Handler проксує живий статус (CORS у Буковеля немає).
- Лише українська мова.
- Фільтр: чотири незалежні перемикачі (зелені / сині / червоні / чорні), лише «сховати».
  Підйомники, що ведуть тільки на сховані траси, теж ховаються.
- План — впорядкований список сегментів (траса/підйомник) з прапорцем «пройдено», одну трасу можна додавати кілька разів. Планів кілька (по днях).
- Планувальник вільний, без графа зв'язків (граф — можлива пізніша фіча).
- GPS: гомографія «координати → піксель карти» за опорними точками (станції підйомників з OSM). Очікувана точність — десятки метрів.

## Дані карти

Карта Буковеля — растровий фон (`public/map/background.webp`, 2865×1648) + SVG-оверлей з лініями.
Фон — оригінальний JPG Буковеля, конвертований у WebP (q82, 1,2 МБ замість 2,3 МБ; `sharp` із залежностей Next).
Усе в SVG намальоване одним помаранчевим кольором, тому колір за складністю задаємо самі (CSS по `data-diff`).

| Файл | Що це |
| --- | --- |
| `data/raw/map-dom.html` | серіалізований DOM `https://bukovel.com/map-new/` (SVG збирається React-ом, тож знімаємо headless Chrome) |
| `data/raw/map-data.json` | `GET /api/v1/ski/map/trails/lifts/` — складність, висоти, довжина, підйомник траси |
| `data/raw/status.json` | `GET /api/v2/status-lifts-trails` — типи, примітки, живий статус |
| `src/data/generated/overlay.svg` | очищений оверлей зі `data-kind` / `data-trail` / `data-diff` / `data-lift` |
| `src/data/generated/resort.json` | нормалізовані траси й підйомники |

Перегенерація: `npm run build:map` (читає `data/raw`, пише в `src/data/generated`).

Оновити сирі дані (кроки вручну):

```bash
curl -o data/raw/map-data.json https://bukovel.com/api/v1/ski/map/trails/lifts/
curl -o data/raw/status.json   https://bukovel.com/api/v2/status-lifts-trails
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --virtual-time-budget=15000 \
  --dump-dom "https://bukovel.com/map-new/?lang=uk&from-site=true" > data/raw/map-dom.html
```

### Пастки в даних Буковеля

- `difficultyLevel` у v2 завжди `BLUE` — ігноруємо. Складність беремо з v1 (`difficulty`); вона збігається з типом у v2 (EASY → blue, MEDIUM → red, HARD → black, PLAYGROUND/TRAINING → green).
- Назва в SVG-id може розходитися з JSON: `Track17ABlue` та `Track-7D-blue` у JSON зелені. Складність завжди беремо з JSON за назвою траси.
- Підйомник 1 в SVG має id `Lift1R`, у JSON — `Lift1`.
- Три безіменні шматки ліній у SVG — продовження трас до станцій; власників задано в `SEGMENT_OWNERS` (`scripts/build-map.mjs`).
- Open-підйомники на сайті мають клас `lift--animated` (рухомі штрихи) — можна повторити для живого статусу.

## Карта в застосунку

- Оверлей вставляється як inline-SVG (`src/components/ski-map.tsx`); фільтр і підсвітка — це перемикання атрибутів `data-hidden` / `data-selected` на групах, без перерендеру React.
- Лінії мають сталу товщину на екрані: CSS-змінна `--zoom` (оновлюється з затримкою після жесту) у `calc(3px / var(--zoom))`.
- Тап по тонкій лінії: у кожну лінію додається прозорий «двійник» `.hit` із товстим штрихом. Мітки й іконки мають пріоритет над хітбоксами (див. `pickGroup`).
- Фільтр ховає також з'єднання (`connector`) і підйомники, усі траси яких приховані. Стан фільтра — `localStorage` (`ski-map:filters`), підтягується в ефекті (`skipHydration`).
- Тап відрізняємо від жесту власним порогом (10 px / 500 мс); відпускання слухаємо на `window`, інакше жест «залипає», якщо відпустити поза картою.

## Плани

- Стор `src/lib/plans-store.ts` (zustand + `localStorage`, ключ `ski-map:plans`): плани → впорядковані елементи `{type: trail|lift, ref, done}`. Одну трасу можна додати кілька разів, кожне входження має свій прапорець.
- Додавання: кнопка «Додати в план» в інфо-панелі вибраної траси/підйомника; якщо планів нема, створюється «День 1».
- Панель плану (`plan-panel.tsx`): тап по рядку — «пройдено», «Змінити» — порядок (▲▼), видалення, перейменування, скидання прогресу, видалення плану; кнопка-приціл показує елемент на карті (і повертає приховану складність).
- На карті елементи активного плану товщі, пройдені — світліші (`data-planned` / `data-done`).
- Резервна копія: експорт у файл / у буфер, імпорт з файлу / з буфера (`plan-io.ts`). Імпорт завжди додає плани як нові (нові id), невідомі траси відкидає й повідомляє.

## Живий статус

- `GET /api/status` (`src/app/api/status/route.ts`) проксує `https://bukovel.com/api/v2/status-lifts-trails` (у Буковеля немає CORS) і віддає нормалізовану форму `{fetchedAt, lifts: {id: {state, from, to}}, trails: {...}}` (`src/lib/live-status.ts`). `state`: `open` / `closed` / `waiting`; невідомі статуси відкидаються.
- Кешування: `Cache-Control: public, s-maxage=60, stale-while-revalidate=300` — CDN Vercel не пускає до Буковеля частіше, ніж раз на хвилину. Помилки віддаються як 502 без кешу.
- `vercel.json` фіксує регіон функції `fra1` (Франкфурт, найближче до Карпат; `preferredRegion` у цій версії Next застарілий).
- Клієнт (`status-store.ts`): останній успішний статус зберігається в `localStorage` (`ski-map:status`), тож без зв'язку карта показує його з позначкою «офлайн, дані від ЧЧ:ХХ». Оновлення: при старті, при поверненні у вкладку, коли з'явилась мережа, раз на 2 хв і по тапу на пілюлю.
- На карті: закрите — приглушене й пунктиром, значок підйомника зелений/помаранчевий/бурштиновий (відкрито/закрито/очікує), без даних — сірий. Запечені в SVG кольори значків підйомників — зі знімка Буковеля, їм не довіряємо. Кнопка «Лише відкриті» ховає закрите.

### Що не перевірено
- **Деплой на Vercel.** Локально Буковель віддає дані звичайному серверному запиту (~0,4 с, без CDN-фільтра), але чи не блокує він IP Vercel, видно лише після деплою. Якщо `/api/status` повертає 502 — дивитись логи функції; запасні варіанти: інший регіон у `vercel.json`, заголовок `User-Agent`.
- **Поля `startDate` / `stopDate`.** Узимку вони, найімовірніше, містять розклад роботи; зараз (міжсезоння) завжди `null`. Показуємо їх у панелі як «09:00–16:00» (час Києва); формат підтверджено лише на синтетичних даних.
- **Статус `waiting`.** Рядок для «очікує відкриття» — припущення за лічильником `waitingCount` в API; реальне значення поля ми ще не бачили.
- Лічильники `counter` в API Буковеля суперечливі (напр., `openCount: 1` і `closeCount: 19` для 19 підйомників), тому рахуємо самі з окремих елементів.

## GPS-точка («я тут»)

Кнопка-приціл під пілюлею статусу вмикає `watchPosition`; точка з'являється на карті (синя крапка зі сталим розміром на екрані + коло похибки в реальних метрах), карта центрується на ній.

**Модель** (`src/lib/geo.ts`, коефіцієнти в `src/data/generated/geo-calibration.json`): карта Буковеля — ілюстрація з перспективою, тому це не афінне перетворення, а перспективна камера 3×4, яка враховує висоту. Висоту під користувачем беремо з «рельєфу», складеного з ліній трас і підйомників (OSM-геометрія + висоти верху/низу з даних Буковеля), а не з GPS-висоти телефона (вона неточна, а модель чутлива: 1 м висоти ≈ 0,34 px).

**Калібрування** (`npm run calibrate:map`, `scripts/calibrate-map.mjs`):
1. Кінці підйомників: пікселі з SVG (`npm run extract:geometry`) ↔ координати з OpenStreetMap (`data/raw/osm-aerialways.json`, збіг за `ref`/`name`). Орієнтацію (який кінець — низ) підбираємо за нев'язкою.
2. Перепідбір камери по кривих трас (ICP): 54 траси з `osm-pistes.json` ↔ піксельні лінії з SVG.
3. Порівняння моделей leave-one-out: афінна ≈ 50 px, гомографія ≈ 49 px, камера ≈ 31 px.

**Точність** (1 px карти ≈ 2,8 м): на непобачених трасах (5-кратна перехресна перевірка) медіана відстані до лінії ≈ 9 px (≈ 25 м), 90-й перцентиль ≈ 36 px (≈ 100 м). Кінці підйомників лягають гірше (≈ 28 px) — їхні лінії в SVG намальовані схематично. Це «приблизно, де я», а не «на якій саме я трасі».

**Поправка**: кнопка «Я насправді тут…» → тап по карті в місці, де ви справді стоїте, зберігає зсув (`ski-map:geo`), який додається до всіх наступних позицій; «Скинути поправку» прибирає його. Корисно, якщо в районі, де катаєтесь, модель систематично зміщена.

**Поза курортом** точки на карті немає, показується підказка («Ви за N км від курорту»). Геолокація працює лише по HTTPS (на Vercel це так; на `localhost` теж) і потребує дозволу в браузері.

Дані OpenStreetMap © OpenStreetMap contributors (ODbL); використовуються лише для калібрування в особистому проєкті.

## PWA й офлайн

Застосунок ставиться на домашній екран і після першого відкриття працює без мережі (карта, фільтри, плани, GPS; статус — останній збережений).

- **Встановлення:** Android/Chrome — меню → «Встановити застосунок»; iPhone/Safari — «Поділитися» → «На екран Додому». Маніфест: `src/app/manifest.ts`, іконки: `public/icons/` (`npm run make:icons` перегенерує PNG із `icon.svg`).
- **Service worker** (`src/sw/service-worker.js`, віддається як `/sw.js` через `src/app/sw.js/route.ts`, який підставляє ідентифікатор збірки, тож кожен деплой дає новий SW і новий кеш). Реєструється лише в продакшні (`PwaRegister`).
  - Встановлення: кешує сторінку, усі `/_next/static/*`-чанки, на які вона посилається, карту (WebP), шрифт, іконки — щоб офлайн працювало одразу, без другого візиту.
  - Сторінка: мережа з таймаутом 3 с, інакше кеш (слабкий сигнал у горах гірший за повну відсутність). `/_next/static/*`: спершу кеш. Карта/шрифт/іконки: з кешу, оновлення у фоні. `/api/*` не чіпає.
  - Оновлення: нова версія не підміняє код під відкритим застосунком; з'являється банер «Доступна нова версія → Оновити» (`SKIP_WAITING` + перезавантаження). Старі кеші видаляються при активації.
- Просимо `navigator.storage.persist()`, щоб браузер не стирав плани при нестачі місця (де підтримується; iOS ігнорує, тож експорт планів лишається страховкою).

**Перевірено** headless Chrome (puppeteer-core) на `next start`: встановлення SW → 9 записів у кеші застосунку + 6 стабільних файлів; перезавантаження без мережі за ~1,6 с з усіма 71 трасами, фоном і шрифтом; завислий сервер (слабкий сигнал) → сторінка з кешу через ≈ 3 с; повний цикл оновлення (новий білд → банер → «Оновити» → старий кеш видалено → знову працює офлайн).
**Не перевірено:** вбудований браузер панелі service worker не реєструє, тож на справжньому iPhone/Android і на Vercel потрібна перевірка руками: відкрити сайт онлайн, додати на екран, увімкнути авіарежим, запустити.

### Вечірнє катання

Чип «Вечірнє» поруч зі «Лише відкриті» лишає на карті тільки вечірні траси, їхні з'єднання й підйомники, що ведуть на них (зараз це 1C, 1E, 2A, 2C, 7A і підйомники 1, 2R, 7). Ознака — примітка Буковеля «Траса доступна для вечірнього катання» (`trail.evening` у `resort.json`, збирається `npm run build:map`). Поле `openFor` у живому API (`DAY` для всіх у міжсезоння) поки не використовується: узимку воно, імовірно, покаже режим роботи трас, але формат ще не бачили.

### Погода

Чип «⛅ −6° 12 м/с» поруч із «План» (температура й вітер на верху) відкриває панель: поточна погода внизу (≈ 900 м) і вгорі (≈ 1370 м, верхня станція підйомника 12), світанок/захід, погодинний прогноз на 24 години (перемикач «Верх/Низ»: температура, вітер/пориви, сніг), попередження про вітер.

- **Джерело:** [Open-Meteo](https://open-meteo.com) (CC BY 4.0, без ключа, безкоштовно для некомерційного використання). CORS відкритий, тож браузер ходить напряму, без проксі: `src/lib/weather.ts` (запит, розбір, коди погоди, рівні вітру) і `src/lib/weather-store.ts`. Один запит на обидві точки з поправкою температури на висоту (`elevation=900,1370`).
- **Оновлення:** при старті, при поверненні у вкладку, раз на 15 хв; не частіше, ніж раз на 5 хв (кнопка ↻ в панелі — примусово). Останній успішний прогноз лежить у `localStorage` (`ski-map:weather`): без зв'язку показується він із позначкою «Немає зв'язку, показано дані від ЧЧ:ХХ».
- **Вітер** у м/с (10 м над землею). Попередження за поривами: ≥ 10 м/с — «поривчастий» (бурштиновий), ≥ 15 м/с — «сильний, підйомники можуть зупинятись» (червоний). Це евристика, а не правило Буковеля.
- Це модельний прогноз із сітки ≈ 1–10 км, а не показники метеостанцій курорту: на гребені вітер буває сильнішим.
- Дані Open-Meteo кешує лише застосунок; service worker запити до іншого домену не чіпає.

### Поділитися планом

Кнопка «Поділитися» в панелі плану (поряд зі «Змінити») показує QR-код і посилання; на пристроях з Web Share API є кнопка «Надіслати…» (системне меню: Telegram, Viber тощо), скрізь — «Копіювати».

- **Без бекенду:** план лежить у самому посиланні: `<сайт>/#p=v1~<назва>~t5K,l13,t7B` (`t` — траса, `l` — підйомник; назва через `encodeURIComponent`, `~` екранується). Код і розбір з валідацією: `src/lib/plan-share.ts`. Позначки «пройдено» не передаються.
- **Прийом:** при відкритті посилання (`SharedPlanDialog`) показується, що прийшло (назва, значки, скільки елементів пропущено як невідомі), і план додається лише після підтвердження. Хеш одразу прибирається з адреси, тож перезавантаження не пропонує додати його вдруге. Невалідне посилання дає повідомлення, дані не чіпаються.
- **Застосунок на екрані і посилання:** на iOS (і часто на Android) посилання відкривається в браузері, а не в встановленому застосунку, а в них окреме сховище. Тому посилання (чи код `v1~…`) приймає й «План → Резервна копія → Вставити / Імпорт з файлу» (`parseAnyImport`).
- QR генерує крихітна бібліотека `uqr` (SVG, без залежностей).

### Розумне планування: чому пропущено

Для підказок «що далі» і перевірки маршруту потрібен граф «з якої траси куди можна поїхати». Автоматично він не складається надійно: за OSM лише для 32 з 63 трас старт збігається з верхом «свого» підйомника, а кінець лежить біля низу підйомника теж у 32 з 63 (решта зливається з іншими трасами); 8 трас в OSM взагалі немає. За самими висотами теж не вийде: біля одного низу в середньому 5–6 підйомників, а для 12 трас немає жодного. Реалістичний шлях — ручна розмітка зв'язків ~70 трас з перевіркою на карті; відкладено.

### Статистика поїздки

Кнопка «Статистика» в заголовку панелі плану відкриває зведення за **всіма** планами-днями (рахуються лише позначені «пройдено»): вертикаль спусків, підйом підйомниками, кілометри трас, кількість спусків і їздок; розбивка по днях (з тривалістю дня за часом першої й останньої відмітки), за складністю, найчастіші траси й підйомники, рекорди (найбільша вертикаль за день, найдовша траса, найвища точка).

- Розрахунок: `src/lib/trip-stats.ts` (чиста функція), UI: `src/components/stats-panel.tsx`.
- Вертикаль і довжини — **за даними Буковеля** (перепад висот і довжина траси), а не за GPS-треком: це оцінка. Траси без довжини/висот у даних (напр., навчальні майданчики 1D, 2D) рахуються як спуск із нулями.
- Час: `PlanItem.doneAt` (мс) ставиться при відмітці й знімається при її скасуванні; входить до експорту/імпорту резервної копії, але **не** до посилань для шарингу. Відмітки, зроблені до цієї версії, часу не мають: день без часу просто показується без тривалості.
- Статистика живе в планах: видалення плану прибирає і його внесок.
